# Google FX 服务管理中心 · 使用说明书

控制台位置：**控制台 → Google FX 服务管理中心**（`console.html` 第一个标签页）。
本文对应 2026-07-26 那批改造（清单见
[google_fx_service_optimization_checklist.md](google_fx_service_optimization_checklist.md)）。

## 0. 三十秒上手

| 我想干什么 | 去哪里 |
|---|---|
| 看服务现在能不能用 | 顶部四张状态卡 + 「运行诊断」 |
| 生成一直卡着，想知道卡在哪 | 「FX 任务队列」里点任务的**阶段**列展开时间线，标红的就是卡点 |
| 怀疑 Flow 改版了 | 「调试与自检」→ **L1 连浏览器不提交**，再看**选择器探针** |
| 出问题了要看现场 | 「失败现场」面板，下载 screenshot.png / page.html |
| 暂时不想接新任务 | 顶部**暂停**（拒新+停派发）或**排空**（拒新+跑完手上的） |
| 改超时/节奏/模型 | 「运行配置」，注意「需重启」标记 |
| 有账号登录失效了 | 号池里状态显示**待人工登录**的那一行 |

## 1. 状态卡与诊断

四张卡分别是**内置运行时 / AdsPower / 执行队列 / 可用账号**。

- **执行队列**副标题是 `N/M 执行 · K 排队 · J 浏览器请求`。M 就是并发度上限
  （默认 1，Flow 画布不是并发安全的）。
- **可用账号**只统计"已真实探测过积分且额度够、未禁用、未冷却"的账号。
  副标题会单列 `未探测` 和 `待登录`。

> ⚠️ 「未探测」不等于「没额度」。新加进号池的账号积分是空的，控制台显示"未探测"
> 而不是编一个数字。选号时会先强制真实探测一次再决定用不用它。

「运行诊断」是给结论的地方，不是罗列指标。会出现的关键条目：

| 诊断 | 含义与处置 |
|---|---|
| `AdsPower 本地 API 端口 XXX 无法连接` | AdsPower 没开，或端口不对（改「运行配置 → 连接」） |
| `N 个账号登录失效` | 去对应 AdsPower 浏览器窗口重新登录，然后点该行「解除冷却」 |
| `N 个任务正在等待人工处理` | 服务在等你，不是卡住了。带剩余秒数 |
| `N 个运行中任务的当前阶段耗时偏长` | 展开时间线看是哪个阶段 |
| `N 组 Flow UI 选择器出现回退或未命中` | 跑「选择器探针」确认；修好后点「清空命中统计」 |
| `IP 轮换处于生效状态` | **不该出现**。实测换 IP 会打失效 Flow 登录 token，本项目默认关停 |
| `上次退出时有 N 个任务仍在队列中` | 服务被强杀过。任务不会自动恢复，点「知道了，清除记录」 |
| `服务处于 paused/draining 模式` | 有人按过暂停/排空，新任务会被拒 |

## 2. 服务控制：暂停 / 排空 / 恢复

- **暂停**：拒收新任务 **且** 停止派发。已经在浏览器里跑的那个继续跑完，
  排队中的原地等着。
- **排空**：拒收新任务，但**继续派发**队列里已有的。适合"我要重启服务，先让它把手上的活干完"。
- **恢复**：回到正常。

这三个动作都会写审计（「操作与队列审计」面板可见），并且状态跨重启保留——
如果重启后发现新任务全被拒，先看顶部徽章是不是还停在「已暂停」。

## 3. 队列与任务

**阶段**列可以点开，展开的是**阶段时间线**：每个阶段进入时刻、驻留时长、
超阈值的标红。这是定位"卡在哪一步"的主要手段——`等工具栏` 空转 180 秒这类问题
在这里是一眼可见的，不用去翻日志。

排队中的任务有三个操作：

- **↑ / ↓**：调优先级（-100~100，数字大的先走）。
- **定向账号**：把这个任务钉在某个 AdsPower 账号上。只能在任务还在排队时钉，
  进入浏览器后才生效并且只影响这一个任务。
- **取消**：发取消信号并立即终态化。**浏览器保持开启**——取消时抽走浏览器会清空
  Flow 画布、打松登录 token，下一单要从头重连重登。

### 调度限额

- **浏览器并发度**：默认 1。调大只在你确认多个 AdsPower profile 真能并行时才有意义。
- **单任务执行超时**：超了由看门狗发取消信号（每 5 秒扫一次）。0 = 不限。
- **排队等待超时**：排太久直接放弃，抛错给调用方。0 = 不限。

## 4. 号池

账号状态的判定优先级：`已禁用 > 待人工登录 > 冷却中 > 未探测 > 额度不足 > 可用`。

- **待人工登录**（`cooldown_reason=login_required`）：2 小时冷却，积分不清零。
  人工重新登录后点「解除冷却」立即恢复。
- **冷却中**（额度耗尽）：24 小时冷却，积分清零。
- **关闭浏览器 / 关闭**：向 AdsPower 发送关闭该账号浏览器实例的 API 指令（`http://127.0.0.1:{port}/api/v1/browser/stop?user_id={user_id}`），释放浏览器进程与 profile 锁。
- **刷新积分**会真的开浏览器读 UI。**生成任务占着浏览器时会返回 409**
  （提示"浏览器正被 X 占用"）——这是刻意的：探针和生成用的是同一个浏览器，
  排队等下去这个请求会挂好几分钟。等任务结束再点。

> 换号只影响当前任务。失败换号（重试前切下一个可用账号）写在任务上下文里，
> 不再改进程级环境变量，所以**不会**让后续别的任务跟着漂到新账号。

## 5. 调试功能（新增）

### 5.1 分级自检

| 级别 | 做什么 | 会不会动浏览器 | 会不会耗额度 |
|---|---|---|---|
| **L0** | 运行时导入、AdsPower 端口、号池状态文件、runtime 可写、IP 轮换配置 | 不会 | 不会 |
| **L1** | 连 CDP、开 Flow、定位 prompt 输入框 / 配置按钮、跑选择器探针、读积分 | 会（排队执行） | 不会 |
| **L2** | L1 全部 + 真的提交一次最小图片请求 | 会 | **会** |

结果按步骤列出，**每步都有耗时**，失败会指明 `失败于：<步骤名>`，
并自动保存一份现场到「失败现场」面板。

排查顺序建议：**L0 → 看诊断 → L1 → 看选择器探针 → 必要时 L2**。
L0 失败时 L1/L2 会跳过浏览器部分（环境都不对，连浏览器只会得到更难解释的错误）。

### 5.2 选择器探针

对 `UI_SELECTORS` 里每个选择器族在当前页面逐层探测，输出三档：

- **主选择器命中**：健康。
- **靠兜底命中**：主选择器已经不管用了，正在用 fallback 撑着——Flow 大概改过版，
  该更新 `ui_selectors.py` 了，但业务还没坏。
- **全未命中**：这一族彻底失效，相关功能一定会失败。

只在弹窗/面板打开后才存在的族（如 `credit_display`）会被标成 `conditional`，
静止页面上缺失不算故障。

修完选择器后点**「清空命中统计」**：统计里的历史 miss 不会自己消失，
不清的话诊断里的漂移警告会一直挂着。

### 5.3 失败现场

以下位置失败时会自动落一份现场到 `runtime/fx_debug/<task_id>/<时间>_<标签>/`：

- 等底部工具栏超时（最常见的卡点）
- 等待人工处理超时
- 自检有失败步骤
- 配置校验未通过

每份含 `screenshot.png`、`page.html`、`page.txt`、`buttons.json`、
`selectors.json`、`meta.json`。控制台可直接点开下载。

数量有上限（默认保留 40 个任务、每任务 20 份），超了删最老的。
不想留可以把「运行配置 → 调试 → 失败时自动保存现场」关掉。

### 5.4 Dry-run

「运行配置 → 调试 → Dry-run」打开后，所有链路走完**全部** DOM 定位、
参考图挂载、配置校验，但**不点发送**。用途：

- 没有账号额度时验证「Flow UI 还认不认得我们」；
- 让 agent 在不消耗额度的前提下复现选择器/定位类问题。

开着的时候顶部「提交模式」会红字提示 `Dry-run 开启（不会真的生成）`——
别忘了关，否则会以为生成失败了。

### 5.5 FX 日志

只筛 FX 相关模块（`GoogleFX`、`账号池`、`积分探针`、`取证`、`自检` …），
支持按 `task_id` 和关键字过滤。比全量日志流实用得多。

## 6. 运行配置

分组：连接 / 模型 / 号池 / 超时 / 节奏 / 去重 / 调试 / 日志。

**「需重启」标记是认真的**：那些字段的读取方是模块导入时求值的常量
（`GOOGLE_FX_DEDUP_TTL_SECONDS`、`GOOGLE_FX_RUN_LOCK_WAIT_SECONDS`、
视频批量强制串行、日志轮转参数），保存后要重启服务才生效。
保存时如果动到了这类字段，toast 会明确列出来。

### 版本栈

每次实际改动都会追加一个版本快照（`runtime/fx_config_versions.jsonl`）：

- **回滚一步**：可以**连续**点，一步一步往前退。
- **重做**：回滚过头了往回走。
- **恢复到选中版本**：下拉框里挑任意历史版本。

无变化的保存不会产生新版本（否则"回滚一步"会退到一个内容相同的版本，看起来像没反应）。

### 值得注意的几项

- **单张图等待上限**：视频按这个值 ×5。
- **两次提交最小/最大间隔**：风控看的是两次提交之间的间隔。图片链和视频链
  共用同一个时间戳，所以一条腿刚跑完好几分钟的情况下不会再白等。
- **重复请求缓存 TTL**：同指纹请求在 TTL 内会**直接复用上次结果、不重新生成**。
  命中时返回值里带 `deduped` 元数据、日志里有明确说明。想让"重跑"一定真跑，设成 0。

## 7. 出问题了怎么查（决策树）

```
任务失败 / 卡住
├── 顶部 AdsPower 卡显示「离线」
│     → AdsPower 没开，或端口不对。改配置 → 连接 → AdsPower 端口
├── 诊断里有「N 个任务正在等待人工处理」
│     → 服务在等你。去那个 AdsPower 窗口登录/过验证，看剩余秒数
├── 诊断里有「N 个账号登录失效」
│     → 重新登录后点该行「解除冷却」
├── 展开任务阶段时间线，有标红阶段
│     ├── 卡在「等工具栏 / 定位」类阶段
│     │     → 跑 L1 自检 + 选择器探针。有 missing 就是 Flow 改版了
│     └── 卡在「等生成结果」类阶段
│           → 看「单张图等待上限」是不是太短；看账号额度
├── 队列一直不动，且「浏览器锁：占用中」但没有活跃任务
│     → 看审计里最后一条 queue.* 记录。理论上不该发生（S1 已修）：
│       现在拿不到兜底锁会在 5 分钟后抛出可诊断错误，不会静默卡死
├── 结果文件像是旧的
│     → 看日志里有没有「命中重复 Google FX 请求缓存」。把去重 TTL 设为 0
└── 都不像
      → L0 自检 → 看「失败现场」最新一条的截图
```

## 9. 交给 agent 修问题时

离线复现夹具在 `tests/fx_fakes.py`：

- `FakeAdsPower` —— 可注入限频、挂死、坏调试端口的假 AdsPower 本地 API；
- `flow_page_html(...)` —— 可按需"改版"的 Flow 关键 DOM；
- `FakePage` —— 够跑选择器探针和取证的极简 Page 替身；
- `DeadListener` —— 端口通但永不响应，复现"AdsPower 把控制台拖死"。

所以「选择器漂移」「卡点」「探针抢浏览器」这类问题都能写成不需要真账号的测试：

```bash
.venv/bin/python -m pytest tests/test_fx_offline_harness.py \
    tests/test_fx_serial_lock_guard.py \
    tests/test_fx_pacing_dedupe_binding.py \
    tests/test_google_fx_console_api.py -q
node --test tests/test_google_fx_console.js
```

给 agent 派活时，附上：**失败现场目录**、**自检输出**、**选择器探针结果**，
以及一条能复现的 pytest 用例名。这三样加起来通常就够定位了。
