# SPARK 接入 Flow2API 视频服务

SPARK 可以单独将视频生成切到 Flow2API。文本、封面与图片生成仍使用各自原有网关；不要将全局 `baseUrl` 或 `apiKey` 改成 Flow2API 的连接信息。

## 服务端配置

先启动本机 Flow2API，并在其后台配置可用账号、浏览器原生生成方式和对应代理。SPARK 的 `server_config.json` 增加以下配置；密钥填写在本机文件中，不提交到 Git，也不填写到浏览器本地存储。

```json
{
  "videoProvider": "flow2api",
  "flow2apiBaseUrl": "http://127.0.0.1:38000/v1",
  "flow2apiApiKey": "填写本机 Flow2API 的 API Key",
  "flow2apiVideoTimeoutSeconds": 1800,
  "flow2apiVideoConcurrency": 3,
  "videoModel": "Omni Flash",
  "videoDuration": "10",
  "videoResolution": "360p",
  "videoRefMode": "VIDEO_FRAMES"
}
```

修改连接地址、密钥或超时后，在没有任务运行时重启 SPARK。也可使用 `SPARK_FLOW2API_BASE_URL`、`SPARK_FLOW2API_API_KEY`、`SPARK_FLOW2API_VIDEO_TIMEOUT_SECONDS` 环境变量；环境变量在服务启动时覆盖文件中的对应字段。`SPARK_VIDEO_PROVIDER` 可指定服务启动时的视频通道。

浏览器请求不能覆盖这三个连接配置。`/api/mode` 只返回安全的视频设置与 `flow2apiConfigured` 布尔值；这个布尔值表示服务端已填写密钥，不是在线健康检查结果。接口响应和配置中心都不显示地址或密钥。

## 页面设置与回读

在配置中心的生成设置中，将“视频生成服务”选为 **Flow2API**，模型选择 **Omni Flash**，参考模式选择 **帧（首尾帧）**。时长、分辨率沿用现有选择；视频画幅沿用当前 `imageAspectRatio`，适配器接受 16:9 和 9:16。

通道、视频模型、时长、分辨率、参考模式会通过 `/api/google-fx/config` 保存到服务端并立即用于新任务。页面加载时从 `/api/mode.video_config` 回读这些设置，覆盖旧浏览器缓存；用户当前画幅、文本模型和图片配置不会被视频回读改写。

切回 `google_fx` 即恢复原 AdsPower 视频通道。Flow2API 的账号由 Flow2API 自身管理，SPARK 不把旧 AdsPower 账号、画布地址或画布媒体 UUID 绑定到新视频请求。

## 并发生成

配置中心选择 Flow2API 后显示「Flow2API 视频并发数」，也可在 Google FX 服务管理中心的「并发」组中修改。范围为 1～10，默认 3；设置 1 恢复串行。服务端保存并通过 `/api/mode.video_config.flow2apiVideoConcurrency` 回读，浏览器生成请求不能覆盖该值；环境变量为 `SPARK_FLOW2API_VIDEO_CONCURRENCY`。此设置独立于 AdsPower 浏览器并发，修改用于下一次生成任务。

已有首尾帧的批量视频使用滚动窗口：同时处理指定数量的片段，一段交付后立即补入下一段。每次尝试使用独立提交编号、原首尾帧和下载路径；回调与 manifest 保存顺序执行，最终结果按原槽位排序。已确认失败或限流在当前槽位按配置重试；结果不明、超时或连接中断保留原收据，停止该槽位的自动重提。账号不可用、认证或 HTTP 访问拒绝在重试耗尽后停止排队中的片段，已发送的其他请求继续结算；取消或收据保存失败则关闭所有活动流并清理未交付文件，保留已持久化的原提交凭据。

视频进度同时列出活跃槽位，例如「并发处理中 3 段：VID 024、VID 045、VID 046」。活跃卡片显示转圈和高亮边框，尚未执行的卡片显示静态沙漏和「等待中」。这里的活跃数量包含准备、上游生成、下载和本地验收；每个项目分别应用并发设置，上游 `/metrics` 则汇总所有项目。刷新或打开项目会接回该项目已有的后台视频任务，不发起新的生成；服务重启后的失败任务不会继续显示为活跃。

「直接生成视频」依赖上一段的真实尾帧，仍逐段执行；前驱本轮失败或真实尾帧提取失败时，后续依赖片段不会使用旧图片提交。视频锚点与过程验收仍按顺序执行；启用耗时 VLM 验收时，实际吞吐会受其影响。

上游 Flow2API 先原子占用候选账号，再进行网络健康检查，避免同时到来的请求反复分配到同一账号。每账号视频并发设置是硬限制，槽位覆盖准备、提交及轮询，并在成功、失败或取消后释放。浏览器池还有自己的总容量；SPARK 并发数超过上游容量时会等待可用槽位。

## 模型映射

以下是适配器接受并精确映射的参数，真实生成验证情况单列在文末。

| SPARK 请求 | Flow2API 模型标识 |
| --- | --- |
| 文生视频，无参考图 | `omni-1.1-flash-{秒数}s-{方向}-{分辨率}` |
| 单张首帧 | `omni-1.1-flash-frames-{秒数}s-{方向}-{分辨率}` |
| 首尾两帧 | `omni-1.1-flash-frames-{秒数}s-{方向}-{分辨率}` |

- 秒数：`4`、`6`、`8`、`10`。
- 方向：16:9 → `landscape`；9:16 → `portrait`。
- 分辨率：`360p` 或 `720p`。
- 首尾帧按“首帧、尾帧”顺序读取本地图片并发送，不能替换成素材参考模式。

例如，10 秒、9:16、360p 的首尾帧请求映射为 `omni-1.1-flash-frames-10s-portrait-360p`；4 秒、16:9、720p 的文生视频映射为 `omni-1.1-flash-4s-landscape-720p`。

普通视频序列的第 N 段仍使用第 N 张与第 N+1 张图片。单首帧展示段保留单首帧输入。“直接生成视频”的第一段使用文生视频，之后每段从前一段视频抽取尾帧作为新的首帧输入。

## 失败、补跑与已有项目

适配器不自动更换模型、缩短时长、降低清晰度、改画幅或切回 AdsPower。模型与参数组合不支持、参考图缺失或无效时，在提交前明确失败；缺失首尾帧不会降级成文生视频。

默认开启 `videoContinuousGeneration`（配置中心“视频自动接续：持续完成”）。一次启动的 SPARK 任务会一直保持运行，自动核对原提交、等待上游恢复、补跑尚未完成的槽位，直到本次目标全部交付后再结束。`videoRetryCount` 为每轮额外重试次数，范围 0–10；轮内次数用完后，按 60、120、240、480、660 秒退避并继续下一轮，没有总轮数上限。明确取消、源帧/配置错误或无法保存进度时停止；选择“仅执行一轮”恢复有限次数行为。

任务通过 `video_recovery` 事件和 manifest 同名记录持久化 querying、waiting、retrying、retry_round、next_retry_at、completed_slots。等待时释放本轮生成的浏览器/账号占用，保留项目互斥；同一 task_id 的 SSE/轮询继续运行，刷新页面会接回当前恢复状态。进度只计算已交付片段，24 段成功加 3 段失败仍显示 24/27；不会提前报告整单完成。

补跑只处理本次目标中的失败或缺失段，成功片段不重复生成。已有 operation、upstream_task 或明确接收证据的尝试持续查询并取回原视频，不另提生成；下载或会话暂时不可用时继续等待。原查询发现新的接收锚点会先写入收据与 manifest。无接收证据且没有 operation 的 Flow 未知尝试，自动核对后可按已有直接补跑策略建立新 submission_id，旧收据继续保留 pending，不能把等待超时当作原任务失败。固定账号 Google FX 的未决保护继续生效。

待确认卡片的“核对原提交”和下载失败后的“取回原视频”仍只查询、下载和验收原结果。显式“重新生成”保持新尝试语义；已接收但尚未结清的原 operation 在持续模式下优先等待原结果。相同 request_id 返回原 SPARK 任务，不启动第二个 worker。视频、帧渲染和分步管线的项目占用保持到 worker 完成清理后释放，取消不会提前放行另一个任务覆盖 manifest。

SPARK 在生成前持久化 submission_id，并以 `X-SPARK-Submission-ID` 传给 Flow2API。原生点击异常会继续读取已捕获请求的响应；仅在确定没有开始放行且独占页面已关闭时允许安全换账号重试。新的 browser_closed、element_detached、click_intercepted、submit_disabled 原因沿用上游 60–600 秒冷却，脱敏诊断保存在原尝试及持久收据中。

已有项目的成功片段继续复用，不因切换视频服务而重新生成。显式重试只替换指定槽位；旧成功视频保留到新视频通过验收并完成落盘后。成功的 Flow2API 片段记录 `provider: "flow2api"` 和具体 `api_model`，便于区分历史片段来源。

视频下载仅接受同一 Flow2API 服务或受限的 Google 媒体域名，每次重定向重新检查，不向下载地址转发 API Key。原始 MP4 经 ffprobe 时长、画幅、分辨率检查与 ffmpeg 完整解码后交付，原音轨保留；后续仍使用 SPARK 既有验收、拼图与合并流程。
