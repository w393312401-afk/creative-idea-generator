# 成片交给 Codex 精剪

在创作结果的成片区展开「交给 Codex 精剪」，选择方式、模型和思考强度，填写可选的补充要求，再开始剪辑。

- **只精剪**：保持当前成片速度，检查并删减穿帮、定格、停顿、重复进退场。
- **精剪并提速**：先精剪，再将施工段相对当前成片加快约 25%；结尾展示保持当前速度。

模型可选 GPT-6.1 Sol、GPT-6 Astra、GPT-6 Sol、GPT-6 Luna，思考强度可选 low、medium、high、xhigh、max；前三款还可选 ultra。首次使用默认 GPT-6.1 Sol + high，已有任务时沿用最近一次受支持的选择作为下次草稿。所选模型和强度随任务保存，并明确传给 Codex；精剪不会自动跟随桌面 App 或 CLI 的全局模型配置。模型负责审阅画面和规划剪点，实际 MP4 仍由技能脚本与 FFmpeg 导出。

历史任务及成片保留原记录。刷新后的未确认提交继续使用原模型和请求编号；没有保存模型的旧提交及待执行任务沿用当时的 GPT-6 Sol + high。草稿中的已移除模型改用 GPT-6.1 Sol，并生成新的提交编号，避免用同一编号提交不同要求。

任务调用运行项目电脑上的 Codex 和 `timelapse-video-editor` 技能，会使用该电脑当前 Codex 登录账号与额度。视频需要已经保存在本项目的 `outputs/` 中。本机页面和已配置的公网地址均可使用；手机或 Windows 浏览器访问公网时，仍由服务器电脑执行剪辑，不需要在访客设备安装 Codex。

精剪完成后默认在成片最后 5 秒烧录透明引导动画，并保留一份无引导版本；可在配置中心「成片引导」关闭、改时长或换成自定义透明视频，见 [成片引导动画](engagement_cta.md)。

原成片保留。每次任务有独立目录，输入先固定为副本，审阅证据、剪辑计划和新 MP4 都放在该目录。完成后可以在精剪面板播放、下载或定位新成片。状态和记录保存在服务端，刷新页面可恢复；取消会等待后台停止，不把未完成视频显示为成品。

精剪开始后，项目卡片与详情显示排队、正在精剪、完成或失败等状态，并显示当前阶段和耗时；运行中约每 4 秒更新。成片区在剪辑设置收起时也会显示进度提示。后台记录的是实际阶段，页面不会估算完成百分比。归档项目集中放在项目模块的「项目归档」分区，可查看或下载保留的成片、节拍数据与全套提示词。

不同成片可以同时精剪，包括分属不同项目的成片。同一成片已有任务在运行时，相同剪辑要求会复用该任务；如需使用不同要求，等当前任务完成或取消后再提交。每个任务独立运行，取消其中一个不会停止其他任务。

运行项目的电脑需要已安装并登录 Codex、安装 `timelapse-video-editor` 技能，以及 FFmpeg、FFprobe、Python 和 Pillow。缺少依赖时面板会显示具体原因；登录与额度问题会在任务运行时提示。技能默认从服务端用户的 `.codex/skills/timelapse-video-editor/SKILL.md` 查找。目前后台执行使用 macOS / Linux 的进程管理，Windows 作为服务器时会提示此入口暂不可用；Windows 浏览器可以使用 Mac 服务器提供的公网精剪。

当前技能的抽帧脚本暂不支持工作目录中的字面 `%`。项目路径含该字符时会在开始前提示重命名，不会启动模型；视频文件名中的 `%` 不受此限制。

## 接入约定

使用官方支持的 [Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)：JSONL 事件用于状态，结构化最终结果用于收取成片；任务限制在工作目录写入，不修改项目源码。没有将网页按钮映射为当前桌面聊天中的消息。

后端以独立任务记录为真源，不覆盖原项目的生成清单，也不把精剪任务混入视频片段生成状态。模型报告完成后，还需要验证实际输出文件及媒体完整性；仅返回建议、命令或文件名不会视为成功。视觉与音轨检查范围留在剪辑记录中，技术验证不等同于逐帧无瑕疵保证。

完成审阅后，后台会保存完整的完成记录。如果 Codex 收尾连续 2 分钟没有返回进展，系统会停止等待，依据已有记录独立核验成片，通过后显示完成；缺少完整记录且连续 10 分钟没有进展时会报超时，并保留原片和已有文件。正在执行的导出或抽帧命令仍使用原有的 2 小时总时限，不会因暂时没有日志被中断。

接口前缀为 `/api/codex-video-editor/`：`GET capabilities` 检查依赖，`GET jobs?source=…` 读取该成片的记录，`POST jobs` 提交剪辑，`POST cancel` 请求停止。提交必须为 JSON；同一提交标识可安全重试。

公网部署在 `server_config.json` 配置明确的来源列表：

```json
"codexEditorAllowedOrigins": ["https://ps.wushi-api.com"]
```

Cloudflare Tunnel 转发到本机服务并保留原 Host。公网接口要求配置中的 HTTPS 来源、同源的浏览器请求及 `X-SPARK-Codex-Editor: 1` 请求头；提交与取消还必须有匹配的 Origin。前端自动发送请求标记及已有访问码，接口不开放跨站 CORS。未配置的公网域名不能使用此入口。本项目当前公网地址固定进入 Mac 的 `spark-mac` 隧道。
