# 「激发维度」页极简布局方案

目标：把左面板从"四个平级的配置分组 + 一个胖页脚"改成"一条看得见的激发流水线"。
不改任何激发/合成逻辑，**所有现有控件 id 原样保留**，只换外壳与位置，因此
`js/config.js` / `js/prompt_pipeline.js` / `js/trend_refs.js` / `app.js` 里按 id
取元素的监听与读值全部不用动。

对照现状：[index.html:150-305](../index.html#L150-L305)、
[css/app/panels-tabs.css:2742-2863](../css/app/panels-tabs.css#L2742-L2863)。

## 一、现在为什么不好用

| 问题 | 具体表现 |
|---|---|
| **看不出"激发"分两次** | 页面上有两个都叫"激发"的动作：`#ideate-refresh-btn`（🎲 换一批灵感 = LLM 激发候选选题）藏在第 3 组的标题行右角，`#generate-btn`（⚡ 激发核心创意点子 = 提示词合成）在粘性页脚。第三个入口 `.compose-action-btn`（卡片上的「一键合成」）又把两步并成一步。三者视觉权重完全不同却互相覆盖，新用户不知道该点哪个、点了哪个。 |
| **因果链被拆成四个等权分组** | 1 参考案例库 → 2 节拍骨架 → 3 灵感卡 → 4 节拍数，实际是"前两个是灵感卡的输入、第三个的选中结果才让第四个和页脚有意义"。四个 `.control-group` 同字号同边距平铺，读不出依赖关系。 |
| **输入区吃掉产出区** | 参考库 `max-height:320px`（手机 230）+ 骨架两张说明卡 + 各组 hint 段落，合计 ≈ 520px 非产出高度；真正要挑的灵感卡挤在下面的横滑轨里，单卡 260×548，窄屏一屏看不全一张卡。 |
| **页脚过重** | 配置摘要（常到 3–4 行）+ LLM 芯片组 + 大按钮，实测 390×844 下约 380px，只剩 238px 的窗口去滚 1000+px 内容——`panels-tabs.css:2742` 那整段移动端补丁就是在给这个结构打补丁。 |
| **摘要信息重复且只在最底下** | `#config-summary-text` 里的 `选题 \| 骨架 \| 复杂度 \| 预算 \| 反差 \| 尺度 \| 拍数`，其中复杂度/预算/反差/尺度四项已是**永久固定的隐藏值**（[index.html:265-274](../index.html#L265-L274)），属于纯噪音；真正会变的只有"选题 / 骨架 / 拍数"三项，而它们要滚到页底才看得到。 |
| **宽屏浪费一大半** | 面板是全宽独占的（`.glass-panel.mobile-active`，见 [base.css:89-106](../css/app/base.css#L89-L106)），1600px 桌面上仍然是一列窄内容 + 右侧大片空白，灵感卡还得横向滚。 |
| **激发中没有过程反馈** | 换一批灵感时 `#ideation-cards-container` 整块被一行 `.ideation-loading` 文案顶掉（[app.js:4360-4363](../app.js#L4360-L4363)），既不知道跑到哪一步、也不知道跑了多久，卡片还全部消失。 |

## 三、五处改动

### A. 激发轨（Spark Rail）—— 核心改动

在 `.panel-header` 下方新增一条 `.spark-rail`，三枚阶段芯片 + 箭头连接：

| 芯片 | 完成判定 | 显示内容 | 点击行为 |
|---|---|---|---|
| ① 取材 | 参考库已选 ≥1 条 **或** 无选中（自动搜）且骨架 ≥1 套 | `3条参考 · 2套骨架` | 展开 A/B 两个抽屉并滚到顶 |
| ② 选题 | `loadedIdeationCover` 有值（点过卡片/节拍简介） | 已选选题名，未选时 `6 张待选` | 滚到灵感卡区；未激发过则触发 `#ideate-refresh-btn` |
| ③ 合成 | `currentIdea` 已产出 | `12拍 · gpt-5.5` | 滚到页脚并聚焦 `#generate-btn` |

三态样式与结果页管线条一致：`未就绪`（灰）/ `进行中`（转圈 + 秒表）/ `已就绪`（✓）。
**激发中的过程反馈全落在这条轨上**：换一批灵感时 ② 转圈并显示 `激发中 12s`，
合成时 ③ 转圈显示 `合成中 · 审核中`；卡片区不再被整块清空，改为保留旧卡 + 骨架占位
（`.ideation-card-skeleton`），所以"上一批还能看"。

这条轨同时替掉页脚的 `#config-summary`（DOM 保留、`display:none`，`updateConfigSummary()`
继续往里写文本，不用动 `js/config.js:66-108`）——因为它显示的 7 项里 4 项是固定隐藏值。

### B. 取材两组压成抽屉行

第 1 组（参考案例库）与第 2 组（节拍骨架）各压成一行 `.spark-drawer`：

* 折叠态一行 = `图标 + 组名 + 摘要 + 该组的动作按钮`。摘要直接复用现有的
  `#trend-refs-selected-note` / `#pacing-skeleton-selected-note`（已在实时更新，白拿）。
* 展开态露出原内容原样：`#trend-refs-list`、`#trend-refs-toolbar`、`#trend-refs-archive-bar`、
  `.pacing-skeleton-options` 全部保持原节点原 id，只是外层多一个 `.spark-drawer-body`。
* 三段常驻 hint（`.trend-refs-hint` / `.trend-refs-direction-hint` / `.pacing-skeleton-hint`）
  移进展开态；折叠态不显示。这是省下的最大一块高度。
* 默认折叠 / 展开规则：首次进入且参考库为空时 ① 抽屉自动展开（引导用户先搜一批）；
  一旦选过参考就默认折叠，状态存 `localStorage`（键 `sparkDrawerOpen`），与
  `picker-collapsed` 那套写法同源。

### C. 灵感卡区成为主体

* `#ideation-cards-container` 从 `display:flex + overflow-x + scroll-snap-type:x`
  改为 `display:grid; grid-template-columns: repeat(auto-fill, minmax(280px, 1fr))`
  （≥1100px），窄屏回落为 `grid-template-columns: 1fr` 的**纵向**列表——手机上横滑轨与
  外层面板的滚动方向打架，改纵向后 `panels-tabs.css:2783-2794` 那段"压低封面/加宽卡片"
  的补丁可以退役。
* 卡内不动一行结构（`renderIdeationCards` 的模板原样），只把三枚动作按钮
  （`.select-action-btn` / `.copy-action-btn` / `.compose-action-btn`）在窄屏改为图标态，
  保留 `title` 与 `aria-label`。
* 选中卡片 `.ideation-card.selected` 的边框加粗 + 右上角 ✓，与 ② 芯片同色，形成
  "轨上的 ② 亮了 = 这张卡被选中了"的对应关系。

### D. 页脚瘦身：摘要框出局，细调进一行

页脚只留两层：

1. **一行细调条**：`#slider-beats` + `#val-beats` + `#beat-count-mode` +
   `#ideation-model-picker`（折叠态一行）。桌面横排，手机压成
   `12拍 · 自适应 · gpt-5.5 ▴` 一行，点 ▴ 才弹出滑杆与芯片组（沿用现成的
   `.picker-collapsed` 机制，只是把作用范围从模型选择器扩到整条细调条）。
2. **一行按钮**：`#ideate-refresh-btn`（从第 3 组标题行搬来）+ `#generate-btn`。
   两枚都保留原 id 原监听，只是**主次由状态决定**：还没选定选题时 🎲 是主按钮、
   ⚡ 置灰；选定后 ⚡ 变主按钮。这是"更方便"的落点——下一步该点哪个由样式指出来，
   不用读文案猜。

`#config-summary` 与 `.btn-shortcut-hint` 在桌面保留（快捷键提示有用），手机隐藏。

### E. 面板标题压成单行

`.panel-header` 的副标题 `<p>配置您想激发的改造或建造项目的核心维度</p>` 在所有宽度隐藏
（移动端已隐藏，见 `panels-tabs.css:2754`）——激发轨本身就是更准确的说明。
标题区 88px → 40px。

## 六、落地顺序（每步可独立验证、可独立回滚）

1. **E + B**：标题压行 + 两个抽屉（纯 CSS + 一段折叠监听）。此步已能让灵感卡上移约 400px。

## 七、落地记录（2026-07-27 已实现）

落地文件：`css/app/dimension-minimal.css`（新增，排在 `panels-tabs.css` 之后）、
`js/spark_rail.js`（新增），改动 `index.html`（左面板重排）、`app.js`（激发中占位 +
骨架点名）、`js/config.js` / `js/trend_refs.js` / `js/prompt_pipeline.js`（各一处刷新调用）。

实现时对上面的方案做了七处调整，都是实测后改的：

1. **标题区不是压成单行，而是整块隐藏。** 顶部 tab 已经高亮着「激发维度」，
   `<h2>概念设定与维度映射</h2>` 是纯装饰；腾出的 ≈50px 直接决定了灵感卡卡底那排
   「🔨 节拍简介 / 复制选题 / 一键合成」能不能落进首屏。想找回标题：删掉
   `dimension-minimal.css` 里 `.spark-minimal .panel-header { display:none }` 即可，
   DOM 原样留着。
2. **抽屉默认一律折叠**，不再按"没勾选参考"自动展开。实测那条规则会在首次进入时
   把 320px 的案例库摊在首屏，灵感卡整个被挤出屏幕——而"没勾选"本来就是可用的默认
   （后端会自动搜一条）。真正需要引导的只有**案例库空着**的情况，改由
   `maybeGuideEmptyRefLibrary()` 在 `renderTrendRefs()` 拿到条数后补开一次，
   且只在用户还没自己动过折叠态时生效。
3. **卡底三枚按钮改回一行**（`flex-wrap: nowrap`）。原来的 2×2 换行是为 260px 定宽
   轨道条目定的；网格里卡片宽 ≈290px，三个按钮一行绰绰有余，省下的一行让最关键的
   「一键合成」进了首屏。封面同时从 180px 压到 150px。
4. **激发轨的状态全部是"读"出来的，没在业务代码里补埋点。** 合成中/已产出直接读
   `generationState.status` 与 `currentIdea`，靠一个 1 秒心跳刷新（状态签名不变时
   不写 DOM），所以 `app.js` 里那 12 处 `generationState.status = ...` 一处都没动。
   唯一需要通知的是"换一批灵感中"——那是 DOM 上看不出来的，由
   `setSparkIdeating()` 在 `loadIdeationCards` 发请求前后各调一次。
5. **页脚按钮主次只用 class，绝不碰 `disabled`。** `#generate-btn` 的 disabled 是
   `app.js` 在生成生命周期里管的（10 多处），抢着改会把"生成中禁用"弄乱。
   未选定选题时 ⚡ 只是视觉上暗一档，仍可点——点了会得到原有的
   「请先点选灵感推荐卡片」toast，那本身就是提示。
6. **`#ideate-refresh-btn` 的文案没有套 `.btn-text`。** `base.css:425` 把该类强制成
   `color:#fff !important`（给 `.pulse-btn` 的深色渐变用），套上去在浅色底的次要按钮
   上就是白字看不见——第一版这么写，截图里那枚按钮只剩一个 🎲。
7. **骨架抽屉的折叠态摘要点名了启用哪几套**（`已启用 2 套 · 单线里程碑 / 内外双重完工`），
   因为折叠后这行是它唯一的露出处。改的是 `app.js` 里 `updateNote()` 一行。

实测数字（Chrome headless，本机 8085 真实页面）：

| 指标 | 改前 | 改后 |
|---|---|---|
| 手机 390×844 可操作窗口 | 238px（见 `panels-tabs.css:2745` 的实测记录） | **495px** |
| 手机页脚高度 | ≈380px | **133px** |
| 手机首屏 | 滚动后才见第一张卡 | **不滚动即见封面 + 标题 + 标签 + 两行正文** |
| 桌面 1600×1000 首屏卡片 | 横滑轨，1–2 张且需横滚 | **4 张完整卡（含卡底三枚按钮），无横向滚动** |

全量测试：`pytest` 1020 passed / 1 skipped，`tests/*.js` 4/4 通过。
（页面控制台仅剩两条与本次无关的 404：`/favicon.ico` 与一张历史封面文件缺失。）

## 八、验收

* 390×844：进入激发维度页，**不滚动**即可看到激发轨、两条抽屉、第一张灵感卡的封面与标题，
  以及页脚两枚按钮；可操作窗口从 238px 增到 ≈560px。
* 1600×900：一屏内看到 4–5 张灵感卡，无横向滚动条。
* 点「🎲 换一批灵感」：② 芯片转圈计秒，旧卡保留并变灰，不再出现整块空白。
* 未选定选题时 ⚡ 置灰且 🎲 为主按钮；点任一卡片后二者主次互换，① ② 芯片同时打 ✓。
* 刷新页面后抽屉折叠态与 LLM 选择保持不变（localStorage）。

以上五条均已在 Chrome headless 上逐条验证通过（浅色 + 暗夜两套主题都过了一遍）。
唯一与预期有差的是"选定的选题不跨刷新保留"——`loadedIdeationCover` 一直只存在内存里
（`saveSelectionState` 只落盘滑杆值），刷新后 ② 会退回"N 张待选"、⚡ 重新变暗。这是
既有行为，不是本次改动引入的；只是激发轨把它**显性化**了。要不要让选题跨刷新保留，
是独立的一个决定（要顺带考虑"隔天打开还接着上次的选题"是否合理），没有在本次动。
