# 手机一键发布 MVP（Tailscale + iOS 快捷指令）

**目标**：把「下载成品视频 → 存封面 → 复制 TikTok 标题 → 切到 App 粘贴」这四步，
压成 **手机上点一下 + 在 TikTok 里粘贴一次**。

**零代码**：不改本项目任何一行代码，只用现成的 `/api/library` 接口。
整套配置一次约 20–30 分钟，之后每次发布都是一次点击。

---

## 它到底帮你省了什么

现在每条成品的三样东西其实都已经躺在库里了，只是手机够不着：

| 要的东西 | 在 `/api/library` 的哪个字段 |
|---|---|
| 成品视频（18–25MB） | `frameRun.merged_video.url` → `/outputs/run_xxx/标题_2x.mp4` |
| 封面 | `activeCoverUrl` → `/outputs/covers/xxx.webp` |
| TikTok 英文标题（含 tags） | `social_title_en` |
| 中文标题（含话题） | `social_title_cn` |

快捷指令做的事就是：**把这四个字段取出来，视频和封面存进相册，标题塞进剪贴板，然后打开 TikTok。**

---

## 第一步：打通手机到电脑的通道（Tailscale）

本机服务只监听 `127.0.0.1:8085`，手机直接连不上。用 Tailscale 组一个私有网络最省心：
不暴露公网、URL 固定不变、走局域网时基本满速下 25MB 视频。

### 1.1 电脑端（macOS）

```bash
brew install --cask tailscale
```

装完打开 Tailscale App，用邮箱/Google 登录。菜单栏出现图标即已连上。

### 1.2 手机端

App Store 装 **Tailscale**，用**同一个账号**登录。两台设备会自动出现在同一个 tailnet 里。

### 1.3 拿到手机能访问的地址

在电脑上执行：

```bash
tailscale serve --bg http://localhost:8085
tailscale serve status
```

`serve status` 会打印出一个形如下面的地址，**这就是你要填进快捷指令的 BASE**：

```
https://flydemacbook-pro.<你的-tailnet>.ts.net/
```

> 为什么要 `tailscale serve` 而不是直接用 `http://100.x.x.x:8085`？
> 因为 `serve` 会给你一个**带真证书的 HTTPS** 地址。快捷指令本身两种都能用，
> 但将来若要做网页版发布箱（见文末），`navigator.share()` 和剪贴板 API
> **强制要求安全上下文**，`http://` 地址会让一键分享静默失效。一步到位省得返工。

### 1.4 手机上验证

Safari 打开 `https://<你的地址>/api/library`，能看到一大段 JSON 就算通了。

> 目前 `server_config.json` 的 `accessCode` 是空的，即无访问码。
> Tailscale 网络本身是私有的（只有你自己登录的设备能连），个人自用不填也安全。
> 如果哪天改用 cloudflared 之类的**公网**隧道，务必先把 `accessCode` 设上。

## 第二步：建快捷指令「一键发布」

打开「快捷指令」App → 右上角 `+` 新建，依次加入以下动作。
**把每一处 `<BASE>` 替换成 1.3 拿到的地址**（结尾不要带 `/`）。

| # | 动作 | 参数 |
|---|---|---|
| 1 | **获取 URL 的内容** | `<BASE>/api/library`，方法 `GET` |
| 2 | **从列表中获取项目** | 「获取」选 `第一个项目`（库是新的在前） |
| 3 | **获取词典值** | 键 `frameRun.merged_video.status` |
| 4 | **如果** | 「如果」输入选第 3 步结果，条件 `等于` `success` |
| 5 | └ **获取词典值** | 键 `social_title_cn`，输入选**第 2 步**的项目 |
| 6 | └ **拷贝到剪贴板** | 输入选第 5 步结果 |
| 7 | └ **获取词典值** | 键 `frameRun.merged_video.url`，输入选**第 2 步** |
| 8 | └ **文本** | 内容：`<BASE>` 紧接着插入第 7 步结果（中间无空格） |
| 9 | └ **获取 URL 的内容** | 输入选第 8 步文本 |
| 10 | └ **存储到照片相簿** | 输入选第 9 步结果 |
| 11 | └ **获取词典值** | 键 `activeCoverUrl`，输入选**第 2 步** |
| 12 | └ **文本** | `<BASE>` + 第 11 步结果 |
| 13 | └ **获取 URL 的内容** | 输入选第 12 步文本 |
| 14 | └ **存储到照片相簿** | 输入选第 13 步结果 |
| 15 | └ **打开 App** | 选 `TikTok` |
| 16 | **否则** | |
| 17 | └ **显示提醒** | 文本：`最新一条还没合成成品视频` |
| 18 | **结束如果** | |

几个容易踩的点：

- **第 3/5/7/11 步的「获取词典值」支持点号路径**，`frameRun.merged_video.url` 可以直接写，
  不用一层层拆。
- **第 5/7/11 步的输入要手动指回第 2 步**，否则会默认接上一步的结果，取不到东西。
  点动作里的输入框 → 在变量列表里选「项目」（第 2 步的输出）。
- **视频和封面的存储顺序别反**：先存视频、后存封面，这样 TikTok 打开相册时
  最新那条就是视频，不用往下翻。
- **URL 里带中文**是正常的，快捷指令会自动编码。极少数标题含空格或括号时若报 404，
  在第 8/12 步的「文本」后面补一个 **「URL 编码」** 动作。

### 放到顺手的地方

指令编好后重命名为「发布」，然后：

- **主屏幕**：详情页 → 添加到主屏幕
- **锁屏/控制中心**：iOS 18+ 可在控制中心加「快捷指令」按钮
- **返回轻点**：设置 → 辅助功能 → 触控 → 轻点背面 → 轻点两下 → 选「发布」

## 第三步：日常怎么用

1. 电脑上跑完合成，确认成品视频已出（网页上「🎬 合并成品视频」那块出现）
2. 手机点一下「发布」→ 等 5–15 秒（视频 20MB 左右）
3. 自动跳进 TikTok → 选相册里最新那条视频
4. 文案框**长按粘贴** —— 标题和 tags 已经在剪贴板里了
5. 需要自定义封面时，在 TikTok 封面选择页选「从相册上传」，选刚存进去的那张

**中英文切换**：如果你主要发英文，把第 5 步的键改成 `social_title_en`。
两个都要就复制一份指令，改个名叫「发布(EN)」。

## 已知的两个粗糙处

这是 MVP，有两个地方能忍就先忍，真嫌烦了再说：

1. **`/api/library` 返回约 917KB**（整库全量，含所有提示词和逐帧记录）。
   快捷指令解析这个 JSON 要 **2–5 秒**，是整个流程里最慢的一环。
   真觉得卡，加一个 10 行的 `/api/publish/latest` 瘦端点就能降到 1KB 以内。

2. **只能发「最新一条」**。想挑着发，在第 2 步之前插入
   「重复项目」+「如果 `frameRun.merged_video.status` 等于 success」
   把合格的标题收集成列表，再用「从列表中选择」让自己手选——
   步骤会多七八个，可靠性也不如直接取第一条。
   更好的解法是做网页版发布箱（下面这段）。

3. **封面是 `.webp`**。iOS 相册能正常存，TikTok 也能上传。
   但小红书等部分国内平台对 webp 自定义封面偶有兼容问题，
   遇到了再加个服务端转 jpg 的参数（Pillow 已在依赖里，约 15 行）。

## 下一步（等你用几天再决定要不要做）

如果 MVP 用下来觉得「只能发最新一条」和「挑不了封面」是真痛点，
再上**网页版发布箱** `mobile.html`：

- 一列卡片，只显示已有成片的条目，一眼看出还剩几条没发
- 每张卡三个按钮：**分享成片**（Web Share API 把视频+文案一起递给系统分享面板，
  TikTok 就在面板里）/ **存封面** / **复制中英标题**
- 「已发」标记写回 `published_at`，避免重发

那套方案的前提就是第一步的 HTTPS 通道——所以这份 MVP 已经把地基打好了。
