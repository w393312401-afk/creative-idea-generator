# 爆款复刻模块排查记录（2026-09-05）

## 本轮修复

| 问题 | 修复结果 |
| --- | --- |
| 查询任务状态时，只重查禁用词，就将视频差量审核失败的任务恢复为完成并入库 | 状态恢复复用完整 `run_audit`，差量违规继续阻断 |
| Windows 没有 `fcntl`，HTTP 与后台线程同时写同一状态文件 | 增加按任务分配的进程内线程锁；POSIX 继续使用文件锁 |
| 锁上下文捕获业务异常后再次 `yield`，覆盖原始报错 | 业务异常原样向上传递 |
| 节拍临时文件在状态锁之外写入，且写入错误被吞掉 | 节拍与状态写入放在同一锁内，写入失败显式报错 |
| 重传原视频复用已归档或源文件缺失的任务 | 去重排除归档、取消、变体及源视频缺失的任务 |
| 归档母本直接删除其变体仍依赖的视频和证据帧 | 有变体依赖时拒绝破坏性归档 |
| 删除母本只检查 `variant_of`，漏掉 `parent_baseline_id` 关系 | 两种父子关系都纳入删除保护 |
| 槽位正文传入字符串列表时报 `AttributeError` | 兼容字符串与字典列表 |
| 快速切任务时旧请求迟到，覆盖新任务 | 用请求序号忽略过期加载响应 |
| 保存节拍期间切任务，保存响应覆盖新任务并可能推进错任务 | 保存后核对任务 ID 与加载序号，变化时停止推进 |
| 推进操作等待保存时再次点击，发出重复请求 | 保存开始前设置忙碌状态 |
| 已锁定母本的合成或普通派生被无条件保存节拍阻断 | 无本地修改的锁定母本跳过保存步骤 |
| 四轴二创直接读取磁盘旧母本，忽略页面上未保存的修改 | 派生前保存脏数据；保存失败不派生，并防止重复点击 |

另修正前端测试夹具：每轮推进恢复空闲状态，保存失败的模拟请求实际记入请求列表，避免测试错误失败或空断言通过。

## 范围与限制

检查了上传去重、抽帧/反推入口、节拍编辑、母本与变体关系、合成审核、归档删除、前端异步操作和相关回归测试。

本轮没有调用真实付费模型或运行完整的视频上传→抽帧→模型反推→合成链路；浏览器检查使用隔离 API。曾启动全仓库测试，但因包含大量范围外测试而中止，改跑上述相关测试，不能将结果表述为全仓库测试通过。

Windows 新增锁覆盖同一服务进程内的线程；不代表多个独立服务进程之间的互斥。写入锁也不等同于所有业务读改写操作的事务隔离。

保留了开始排查前工作区已有的未提交修改。本轮业务代码修改限于 `replica_pipeline.py` 与 `js/replica_pipeline.js`，另外新增/调整回归测试及本记录。未对用户现有任务执行删除或归档。
