# 人物身份、外观与状态连续性

在制作含人物的生成阶梯、修复换人／换装穿帮或验收实际画面时读取本文件。人物身份与 [空间、人体比例](spatial-consistency.md) 分开检查：同一张脸不能证明尺度正确，尺度稳定也不能证明没有换人。

纯反推只记录可见特征、来源帧和未知项，不替源片设计新人物。看不清脸、鞋或衣服背面时保持未知；不能从工种猜年龄、肤色，也不能从画面猜精确身高。

## 1. 一个人物，一份可继承基准

新制作含人物的提示词包，在 `spatial_contract.actors` 为每个人物建立唯一 `id`。同一人物跨机位、跨段、跨空间沿用该 ID；新增第二个人物才另建 ID，不因换装或戴口罩换 ID。

| 项目 | 基准里需要确定的内容 |
|---|---|
| 身份来源 | 同一组已存在且已审阅的参考文件／源片帧；参考缺失时明确待制作，不冒认已有附件。 |
| 脸与年龄外观 | 可辨认的脸型、五官特征及年龄外观范围；不强求精确年龄，不把表情当身份特征。 |
| 头发与肤色 | 发型、长度、颜色、可见胡须；稳定的肤色基准，允许光照和沾污改变当下外观。 |
| 身体 | 体型、肩胯关系、四肢与躯干比例；世界身高及其依据另记，不以瘦高等形容词代替尺度。 |
| 服装、鞋与配件 | 可识别的款式、颜色、层次、袖口、裤型、鞋和实际可见配件；仅记录本题需要的细节。 |
| 初始状态 | 衣物洁净／污损、袖口位置、手套、防护装备及携带物等当前状态。 |

`appearance` 与 `state_baseline` 写具体完整文字，不能交付“固定脸型／服装待定”等模板占位。原创设计可先选定外观，明确它是设计；按源片复刻时只沿用已见特征，需补足的未知外观单列为生成设计。

用户只给部分原创外观时，沿用所有指定特征，补足身份辨识和镜头继承实际需要的最少特征，例如脸型与年龄外观范围；不为填满表格增加纹身、饰品或其它无关设定。参考片中不可见的特征保持未知，只有生成确实需要时才明确另设设计。

外观基准固定可识别身份，不锁死姿势、表情、视线、动作、呼吸、衣料褶皱和光照。不要要求工人在所有镜头正脸站直，也不要把逆光、俯视或遮挡引起的差异自动判为换人。

## 2. 参考要真实可用，引用服从实际工具

参考优先使用同一人物清楚的全身和脸部视图；手部／袖口承担大量接触特写时，再补能够核对的局部参考。可以从同一源片取得，不强制另外生成一套角色图。

- 检查参考之间确实是同一人、同一外观基准。多张相互矛盾的照片不能靠写“保持一致”合并。
- 已有参考记录实际路径、帧时间或资产标识，并说明它支持脸、全身还是局部判断。用户给的真实图片、已生成并审阅的角色图都可作为参考。
- 尚未生成／选出的参考在 `reference_source` 明确写 `planned` 和用途；提示词可完整交付，但不能说已经上传、绑定或完成身份验收。
- 工具支持人物／实体参考时使用同一已核验资产；只支持首尾帧、普通附件或文字时，按当次能力传入。不可凭空声明专用人物字段、固定权重或永久一致性保证。
- 若必须换参考，先核对新旧身份、体型和外观状态；修正人物基准及受影响段，不把错误参考继续传给后续镜头。

人物设计参考不占用 N+1 空间状态图号。空间状态图与最终 reveal 默认无人，人物校尺放辅助设计参考或实际动作帧；用户明确要求有人时按其安排记录。

### 把参考传进实际入口

实际渲染时记录参考文件及其用途、已审阅范围、传入角色与实际提交证据。区分 `planned`、已生成、已审阅和已绑定；本地文件存在或提示词写了“same person”都不证明已绑定。

- 能另传人物／实体参考：将已核验人物图与对应场景锚点一起传入，每段核对实际资产和顺序。
- 只接受首尾两张图：文字身份无视觉绑定保障。人物一致性优先的渲染可从已核验无人场景与同一人物参考合成独立动作首／尾锚点；同一人放在真实作业位置，头脸可读、脚落在已知承托面。分别保留原无人状态、动作图、来源及映射，不把合成参考写成原片事实。下一段继承已核验动作边界或前段真实动作帧，避免每段重抽人物。
- 动作锚点的姿态、PPE、工具和工作进度必须符合边界状态；不能为绑定身份把尚未戴好的手套提前画好。最终无人边界仍为空景，不把人物带入用户未要求的 reveal。
- 入口自动改写后比较实际正文与人物、空间合同：新增假身高、固定屏幕百分比、改性别／衣服、删关键状态变化都算冲突。优先采用能保留合同的本次请求设置，并记录设置；不能以原始提示词正确代替实际输入检查，也不擅自改全局配置。

这条动作锚点路径只用于确实需要渲染且入口缺少独立人物绑定的情况，不强制所有纯文本包改成有人状态图。工具是否支持附加参考以当次接口为准，不虚构专用字段。

### 构图要提供身份与尺度证据

先选作业机位，再检查：工作姿态时头顶和定义发型留在画内、脸有可辨特征，至少一个工作宽镜同时展示身体、脚下承托面与相关尺度参照。头发顶部和需要观察的鞋底与画幅边缘之间保留足够留白；贴着上沿的头发、尚未露全的鞋或未见承托面的桌腿不能按完整证据验收。按实际分辨率检查留白，不设人物占画面的固定比例。相机太近或俯角太大时，移动相机或改变合理视角；不靠缩小人物、扩大场景或只裁掉头来适配空场景构图。

脸不必每帧正对相机，接触特写也不必露全脸。狭窄入口、被搬物件或真实墙体挡住人物时，接受物理遮挡，在遮挡前后用自然工作视角复核身份；不能为了露出两张脸把工人挤到柜体旁边、改成不可能的并排通行或让人透过物件。身体转向、遮挡或跨空间之后安排自然可读的工作视角继承同一基准；不用与工作无关的站姿合影替代过程。先让参考和构图可验证，再加身份文字，避免只堆重复外观形容词。按实际输出分辨率检查细小动作是否读得清：必要的手指穿入、握持或交接可使用接触／中近景，完整关键转换留在同一可读镜头；身份和整体尺度由前后工作镜头核对，不要求每个细节镜头同时装下全身。不能把事后放大低分辨率帧当成新增动作证据。

## 3. 变化有状态来源，跨镜头继续继承

换装、脱外套、卷袖、戴手套／护目镜、沾尘、受湿及清洗都可发生。为相关节拍写清变化前、变化后及原因；可以是可见动作、明确时间跳转或用户指定状态，不必为每个小变化插入独立镜头。

污损会延续到后续段，直到存在清理或换装来源。不能切特写突然多一副手套、返回宽镜又消失；衣物不能在无人边界间自动恢复洁净。防护遮住脸时，继承可见头发、服装和身体特征，不因看不见五官而虚构确认。

工具和材料属于动作状态，记录拿起、放下或交接；不把每段换工具当作身份变化。手套、手表等在左右手的位置有证据时沿用，翻转画面或遮挡造成的疑点先复核，不凭单帧强判。

左右手、已穿戴装备或物件数量发生漂移时，先减少关键转换内的机位与站位变化：同一可读中景保持躯干到双腕的连接，参考锚点采用同一朝向，明确解剖左右与当前画面侧的对应；只在固定朝向成立时沿用这组画面侧描述。剩余物件保留在可识别的固定位置，分别记录未用、手持、已穿戴的数量和路径，不靠切镜重置。不要为防翻转额外编造纹身、标签或标记。

固定朝向仍重复发生穿戴／交接漂移时，在段数与总时长约束允许的范围内，把目标手、接触物和开口方向明确画进尚未完成动作的中间边界，再拆开取用／撑口与插入／穿戴。例如已戴右手套保留在原腕，右手从外侧撑住第二只空手套的朝上开口，裸露左手指仍在开口外；前段实际达到并核对这一状态后，下一段才完成左手插入。不得把中间图预先画成双手已戴，或省掉取用来源，以此绕过失败过程。

依赖前段穿戴、交接或搬运状态的续生成，先核对前段真实末端及相邻帧，确认状态、来源和左右关系后再衔接；理想锚点正确不能抵消实际视频边界错误。可共用已核验的同一中间参考，或使用审阅过的实际动作帧，但不能把未通过的前段直接当作已完成工序。

需要看见完整状态变化时，将它列为本段不可省略的事件：变化前可读、动作发生、变化后可读，再进入依赖它的操作。双手穿戴分别完成，两名工人的交接分别确认；不能用一个剪切把第二步、工具取用和下一道工序一起省掉。复杂穿戴与施工塞不进所定时长时，在段数允许的范围内拆成独立准备／施工片段，保持原工序和最终成果。用户已锁段数或总时长时，先调整允许的分镜和重复劳动压缩；仍不兼容则说明约束与具体调整建议，不能默默增加片段、删动作或静止等待凑时长。

多人分别维护 ID、基准和状态，写清各自的动作与位置。不同人物不能共用一份脸部参考，也不能在切镜后互换衣服、任务或身高。

## 4. 有人段能独立复制，并保留接触连续性

每个有人生成段填写 `actor_ids`，无人段明确写 `[]`。人物表存在时，引用必须对应其中的 ID；只做观察时不强迫建立生成人物表。具体字段规则见 [交付包合同](package-contract.md)。

有人段正文自含该人物核心识别特征、服装／体型和本段变化状态，沿用实际可用的同一参考及世界尺度关系；不能只写“同上一段”或只有内部 ID。每段不必重复不可见的全部五官、鞋底和配件，细节以当前画面能核对的内容为准。

- 宽镜进入特写：手、肤色、手套、袖口、工具与接触面来自宽镜中的同一人物和当前状态；局部镜头不能生成另一套手或衣袖。
- 返回宽镜：恢复同一人物身份、服装和已发生的局部进度，允许动作姿势继续改变；不能因特写挡住脸而重新抽取人物。
- 跨空间：身份与状态一起经过入口或切镜，世界身高和身体比例继续继承；比例判断按空间手册排除深度、姿态与相机影响。

适配工具时把人物基准、可用参考和本镜空间关系放入实际生效的入口，不能只放在交付说明里。若工具无法传入独立人物参考，保留文字基准并记录约束局限，不为方便绑定把人物画进默认无人终态。

## 5. 结构记录与身高归属

字段类型、JSON 示例和引用校验统一见 [交付包合同：人物合同与逐段引用](package-contract.md)。人物参考、外观和初始状态保存在人物表，逐段引用及变化保存在生成段和审核记录；这些字段不会自动替代导出的完整英文正文。

全局 `reference_height_m` 保留单人旧包兼容；新包的人物身高优先分别记在 `actors[].height_m`。多人分别记 H_worker_01、H_worker_02，或各自有依据的数值；可以用一个共同单位表达两者的比值，不能把同一个 H 直接当成所有人的身高。

`reference_actor_id` 可选，用于明确全局 H 对应哪个人物。身高数值与全局参照同时出现时保持一致；身高依据分清已知、估计、设计和未知。未知身高可为 `null`，不妨碍身份设计和相对尺度检查。

## 6. 身份验收与尺度验收分别留证据

文本检查：人物 ID／参考是否统一，各段核心外观是否相容，换装与污损是否有来源，特写与返回是否继承手／袖口，人物引用和无人安排是否吻合。结构校验无法判断真实照片是否同一人，也无法替代正文语义检查。

实际生成后，在人物清楚可见的开工、中段、收尾、转身／遮挡及宽镜→特写→返回处核对，疑似漂移再加密。脸部不可辨时身份标待复核，不能把模糊画面算通过；尺度另以可比深度、姿态和固定实体复核。

审核记录分别写“人物身份／外观”与“人体／场景尺度”的通过、失败、待复核或未渲染，附帧时间及具体依据。文本包的 `render_review.status` 保持 `not_run`；无人首尾帧通过不证明动作中段的人物合格。

失败时先判断是基准冲突、引用失效、状态漏继承还是生成漂移，再修对应参考和段落并复核相邻边界。重试上限与授权沿用空间手册，不靠补更多重复形容词、强行固定表情或删除全部人物宣称问题已解决。
